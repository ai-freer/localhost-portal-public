# Personal Portal

把常用服务、项目入口和分享资料放进一个可搜索的个人导航页，也可以让 AI 按统一规则维护内容和卡片配图。

纯静态 HTML、CSS 和 JavaScript，无后端、无需安装前端依赖或构建。服务与分享分为两个空间，顶部统一搜索；卡片支持深浅主题、分类、编辑和配置导入导出。卡片支持本地原生截图与裁切，加载失败时保留 SVG 或白卡，不依赖远程图片服务。

**当前状态：本地发布候选稿，尚未公开发布，采用 [MIT 许可证](LICENSE)。** 示例全部使用 example.com 虚构地址和虚构内容；打开示例链接不代表有对应的真实服务。

## 先运行起来

需要 Python 3（本次验证使用 3.13）和现代浏览器。Node.js 只用于开发检查，日常运行不需要。自启动脚本只支持 macOS；手动 HTTP 启动可用于其他安装了 Python 的系统。

取得项目文件后，在终端进入包含 `index.html` 的目录，再运行：

```bash
python3 portal_server.py --port 7576
```

Windows 若没有 `python3` 命令，可改为：

```powershell
py -3 portal_server.py --port 7576
```

在浏览器打开 [本机导航](http://127.0.0.1:7576)。看到“我的服务”中的 4 张示例卡片，切换“分享链接”看到 6 张示例卡片，即完成首次加载。按 `Ctrl+C` 停止终端里的服务。

不要直接双击 HTML。若端口被占用，换一个端口，同时修改浏览器地址。`127.0.0.1` 始终指当前电脑；导航不会替你安装卡片所指向的应用，也不会自动建立 SSH 隧道。

内置服务器仅监听本机，并只提供 `portal_server.py` 中明确列出的运行文件。Git 元数据、文档、脚本、目录列表和符号链接均不会通过 HTTP 提供。请使用此启动命令；换成通用目录服务器会失去这项保护。新增运行资源需同步审查服务器白名单；当前空的卡片媒体配置无需额外图片资源。公开部署与访问控制需要另行设计。

## macOS 登录自启动

先停止上面手动启动的 HTTP 服务，避免占用同一端口。然后在项目目录执行：

```bash
./install-autostart.sh --port 7576
```

安装后立即启动，以后在当前用户登录时启动；进程退出会自动恢复。脚本识别自身所在项目目录，只监听本机，不需要 sudo；端口占用或已有安装会报错，不停止其他服务。

仅查看将生成的配置：

```bash
./install-autostart.sh --dry-run --port 7576
```

不再需要自启动时，再单独执行：

```bash
./uninstall-autostart.sh
```

卸载保留项目文件和收藏。改端口、移动目录、换电脑及日志说明见 [AUTOSTART.md](AUTOSTART.md)。未实测系统重启或退出后重新登录；已经实测安装、进程自动恢复和卸载。

## 填入自己的内容

有两种方式：

- **在页面编辑**：添加服务或分享，使用卡片菜单修改、删除。适合日常少量维护。
- **修改配置文件**：自己编辑 JSON，或让 AI 修改。适合批量整理、分类和制作配图。

| 文件 | 维护内容 |
| --- | --- |
| `instance.json` | 站点名称、分类图标与配色、排序规则、浏览器存储键 |
| `services.json` | 服务入口、搜索别名、备注和非网页连接串 |
| `shares.json` | 报告、资料等分享条目，以及日期和配图引用 |
| `artwork.json` | 各分享条目的 SVG 线稿 |

例如，要增加网页服务，可把下面条目加入 `services.json` 的 `services` 数组，再把示例地址替换成自己的地址：

```json
{
  "id": "my-workbench",
  "name": "我的工作台",
  "url": "https://example.com/my-workbench",
  "category": "工具",
  "aliases": ["workbench"],
  "emoji": "🧰",
  "note": "日常工作入口"
}
```

不要把整个文件替换成单条记录。新增分享、分类和配图的完整说明见 [CONFIGURATION.md](CONFIGURATION.md) 与 [SHARE_CARD_STYLE.md](SHARE_CARD_STYLE.md)。演示配置关闭了服务探测；需要检测时在 `instance.json` 将 `probeServices` 改为 `true`。“可达”只代表收到 HTTP 响应，不证明登录成功或应用健康。

### 保存与备份要分清

页面编辑只保存当前浏览器，不会写回 JSON，也不会自动进入 Git。要备份：

1. 在服务“配置”菜单导出服务，在“分享配置”菜单导出分享。
2. 核对下载内容，写回对应的 `services.json`、`shares.json`。
3. 连同 `instance.json` 和 `artwork.json` 保存到自己的私有备份。

已有浏览器收藏优先于文件配置。修改文件后，如果页面仍显示旧内容，先导出浏览器尚未备份的修改，再合并并导入；提高 `version` 不会覆盖收藏。导入会替换对应空间，两个空间分别操作。

第一次建立个人实例时可设置自己的 storage 前缀；使用后不要随意改键。不同端口、`localhost` 和 `127.0.0.1` 是不同浏览器来源，收藏不会自动互通。换端口或设备前先导出。

## 让 AI 帮你使用和维护

本项目自带 [portal-maintainer Skill](skills/portal-maintainer/SKILL.md)。能读取项目文件的 AI 不需要安装插件，只需按下面的提示读取文档：

```text
请在我指定的 Personal Portal 项目目录工作。
先读取 AGENTS.md 和 skills/portal-maintainer/SKILL.md，按任务需要查阅其他文档。
本次任务：帮我启动导航，并把下列链接加入合适的空间和分类。
保留已有内容，核对是否有未导出的浏览器编辑；新增分享时绘制对应线稿。
只修改这个实例，不安装自启动或发布网站，除非我另行要求。
项目目录：填写我的实际项目目录
链接信息：填写标题、完整 URL、用途、可选分类/日期/别名
```

也可以把任务改为“为现有卡片换配图”“导出并合并收藏”“按指定端口安装自启动”。Skill 说明了启动、配置、维护和备份的不同处理流程。支持 Skills 的客户端可自行安装整个 `skills/portal-maintainer` 文件夹；项目不会自动修改客户端设置。没有浏览器能力的 AI 可以修改文件，但必须说明没有验证页面或浏览器收藏。

## 搜索与快捷入口

- 顶部搜索两个空间；空间内搜索只筛选当前空间和分类。
- `⌘K` / `Ctrl+K` 或 `/` 聚焦全局搜索。
- 浏览器自定义搜索引擎关键字可设为 `go`，地址填 `http://127.0.0.1:7576/?q=%s`；端口不同则同步修改。
- `?q=` 唯一匹配会倒计时打开，可以取消；手动输入不会自动倒计时。
- 分享在新标签页打开；非网页服务复制连接串。

## 公共框架与个人实例

建议使用两个独立目录：一个维护公共框架和虚构示例，一个保存自己使用的完整程序及真实配置。个人实例可以保存在独立私有仓，作为实际运行与恢复备份。

两个目录不会自动同步。通用功能在框架目录开发和验证后，按 `framework.json` 清单审查并更新个人实例；保留四份实例 JSON、存储键和本机生成的自启动配置。不要整目录覆盖，也不要把个人仓历史合并回公共仓。

运行完整备份不依赖临时下载公共框架。模板本身不提供账号登录、云同步或目标服务安装。Git 仓私有不等于部署的网站私有。

## 开发检查

在项目根目录运行（本次验证使用 Node.js 22、Python 3.13）：

```bash
node --test config.test.cjs git-privacy.test.cjs card-media.test.cjs
python3 autostart.test.py
python3 server.test.py
node check-public.cjs --identity-file .git/approved-public-identities.json
```

前四项检查配置、保存规则、自启动、HTTP 隔离与 Git 隐私检查逻辑。最后一项只适用于保持虚构示例的发布候选稿；填写真实内容的个人实例不应为了通过它而删除自己的配置。

该脚本检查当前文件白名单、示例 URL 和部分敏感模式，并审查所有分支/标签可达的提交作者、提交者、标签作者、消息及历史文件对象（包括已删除文件），同时检查下次提交实际使用的身份。不会修改 Git 配置或历史。

公开身份需要使用 GitHub 提供的 noreply 邮箱，并显式批准姓名与邮箱组合。把批准列表放在仓库外的 JSON 文件中，格式为 `[{"name":"公开署名","email":"GitHub 设置中提供的 noreply 邮箱"}]`，运行 `node check-public.cjs --identity-file /path/to/approved-identities.json`。未提供列表、历史身份不合规或下次提交身份不合规均返回失败；不要为消除提示而批准私人邮箱。

检查不是完整秘密扫描器：不会扫描不可达对象、reflog 或截图像素，也不能识别所有私人域名和文本。通过后仍需人工审查待上传内容与许可证。当前本地候选稿已修正原有提交身份并完成审查，尚未推送或公开发布。身份批准文件仅保存在本机 .git/approved-public-identities.json，不进入提交；其他维护者需按上面的格式建立自己的批准列表。

视觉变化还应实际检查桌面 1440×1000、手机 390×844 的深浅主题。目录布局和详细绘图要求以项目文档为准。
