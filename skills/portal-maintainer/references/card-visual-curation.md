# 卡片选图与内容提取完整流程

此文档随公版 portal-maintainer Skill 维护，个人实例只同步副本。


将每张卡片视为网站设计的一部分：读懂内容，挑出值得露出的画面，让用户能辨认目的地，同时保持标题与操作清楚。不是机械地批量截取所有首页。

## 先确定工作范围

读取目标项目 README、AGENTS 和卡片视觉规范，沿用其密度、排版与配置结构。用户要求试验时，在独立目录和独立预览地址工作，不改运行目录、启动配置或正式收藏。不要把视觉方案认可推定为全站替换或部署授权。

新增配图与刷新旧图分开处理。记录哪些条目已有用户选定配图。临时抓取失败不替换合格旧图；没有合适素材时维持现状，不能用错误页、加载页或通用占位图覆盖旧卡。

## 三级素材策略

### Level 1：真实内容与官方视觉

有稳定官方标识和视觉形象的成熟软件，优先检查官网、官方品牌包或官方仓库；用于识别产品时，官方 CI 往往比截取杂乱控制台更适合。保持原色、完整比例与必要留白，不重绘成近似图标，不靠任意裁切、变色、透明遮罩破坏标识。优先使用官方提供的深浅色版本；需要中性承托面时使用与原标识匹配的明暗底色。官方素材与正文截图同属真实来源，不计为生成封面；记录来源、版本/抓取日期及要求的归属说明。

品牌识别与卡片作用分开：同一软件的控制台仍可打开网页，API/数据库卡则明确说明连接用途并复制地址。品牌图片加载失败保留原 SVG/图标，不影响操作。官网素材或品牌包暂时不可获取时，不使用未经确认的第三方改绘版本冒充官方。

阅读标题、摘要、目录和相关正文，寻找最能代表页面的真实视觉。首页与正文核心图处于同一层级，不必优先首页：

- 工具或网站：可辨识的首页、核心工作界面、场景主体。
- 报告：核心架构图、流程图、内容总览、关键对比图，或具有代表性的封面。原生 HTML/CSS 的时间线、状态卡、分栏、表格、问题分组与有辨识度的标题排版同样是 Level 1，可直接截取内容区块；不能把“没有 img/SVG”误判为“没有视觉素材”。
- 只挑真实出现的内容，不拼出不存在的界面或改变图中关系。

根据主题相关性、缩小后的辨识度、构图适配和文字干扰选图。通常查看首页及最有价值的 1–2 个正文候选即可；不是只凭页面有图片就采用。题材或内容重要时可投入更多阅读，避免无目的地截完整站点。

源图清晰且能独立表达时优先复用原始图，否则截图。架构图应保留有意义的关系整体；如果只能靠读小字才能理解，或裁切会改变含义，不宜充当卡片背景。给每张图选择合适的裁切重心，避开菜单、空白、无关大标题和浮层。收紧到时间线节点、状态数字、色条与分栏结构；不要把整页缩成小字。保留图中必要关系，不用局部露出伪装完整数据结论。

加载完成后检查实际截图。登录提示、错误、骨架屏、空白、未加载图表不算合格首页。避免把浏览器扩展浮窗及不应露出的账号或私人数据带入素材。优先使用已授权访问、无扩展干扰的采集环境，不为截图修改源站。

### Level 2：根据内容生成封面

必须检查原生内容区块并实际裁切试验后，才能判断 Level 1 不适用。优先保留源页面字体、色板、排版与系列报告的一致性，不因原页面素雅、文字较多或不够插画化就进入 Level 2。Level 1 确实找不到适合卡片的真实视觉时，先以可靠正文提炼主题，再生成概念封面；生成风格应延续源页面，避免擅自套用玻璃、金属等异质视觉。无法读取内容时，利用已有摘要；信息不足则保留旧图，不能仅凭一个含糊标题虚构报告内容。

生成的是主题表达，不是假装真实的数据图或产品截图。避免虚构数据、结论、精确架构、业务状态与品牌标志。构图服务卡片：主体集中于露出区，阅读区留白，减少小字和装饰。相近系列保持视觉语言，具体条目保留可辨差异。

在 Codex/ChatGPT 使用宿主内置生图工具，遵守用户指定供应商与费用边界，不从其他 Agent 配置自动选第三方。内部元数据标记 generated，不与真实证据混淆。工具不可用、结果不合格或本次范围不含生图时，进入 Level 3 或保留原样。

### Level 3：内容 SVG 兜底

沿用项目已有的分享卡片 SVG 规则：根据内容选一个核心意象，以少量辅助元素解释主题；保持原图层尺度、线条层级和主题颜色，不用通用图标冒充专属配图。

无网页的 API、数据库、缓存等服务应先判断用途：它们通常是供程序或客户端连接的地址，而不是浏览器页面。需要保留为连接入口时，使用对应服务类型的 SVG 图标和内容线稿，明确标注“模型接口 / 数据库地址 / 缓存地址”，主操作为“复制地址”，不以白卡或虚构网页封面充数。不能仅凭端口存在推断有其他程序正在使用；是否保留由实际使用或地址记录需求决定，不擅自删除收藏。网页服务暂时不可访问时仍保留原有兜底，不借此伪造首页。已有合格 SVG 无需因本次抓取失败而重画。

## 统一视觉，但不强制每张图用同一参数

- 统一卡片轮廓、字号、留白、图层区域和操作位置；内容颜色允许不同。
- 先调整素材和裁切，再考虑增强对比、饱和度或透明度。不要把所有图都洗成灰白，也不要只靠给文字加重阴影解决冲突。
- 当前认可的卡片方向为右侧高露出：无文字覆盖的右上区域目标约 80%–90% 原图贡献；向左侧标题与底部操作渐隐。这个数字是叠加蒙版后的目标，不是单个 img opacity 值。
- 明亮图、暗色图、照片与架构图可分别调节；标题跨入图像时优先局部柔边底色，保留右侧完整色彩。检查柔边是否形成明显光圈或难看的文字底块。
- 同时看单卡与整组网格：颜色可以丰富，但避免一张极亮、极杂或高对比的卡片压过所有邻卡。降低个别异常卡的视觉强度，不全局抹平差异。
- 长标题正常换行，不能为了图像隐藏必要标题、改变卡片密度或牺牲操作可读性。

## 素材与配置保护

把图片保存为本地静态资产，页面不实时嵌入远程网页、不在每次加载时截屏。使用实例 card-media.json 按空间与完整 URL 关联，保留查询参数和锚点。图片放在实例 assets/card-media/，不进入公版。原图保持不变，crop 保存原图像素坐标 x/y/width/height，sourceSize 保存原图宽高；裁切必须在边界内。

建议每张图记录：条目 ID / 完整源 URL、素材类型与层级、源页面或图地址、选用理由、抓取或生成时间、本地文件、裁切重心、必要的主题参数。保留生成与真实素材的来源区别。

不更改条目名称、URL、分类、顺序、收藏、个人配置和 localStorage 版本来强制刷新配图。服务和分享保持独立。用稳定标识关联；URL 去重不应删除有意义的查询参数。未映射或图片加载失败时回退到该条目原有 SVG / 白卡。资源替换只在验证合格后进行，失败保留上一个可用版本。

## 验证与交付

在实际卡片尺寸查看图像，不以大图好看来代替卡片效果。按项目要求检查桌面深浅色、手机、长标题与成组卡片；检查文字与背景是否竞争、核心物体是否被裁切、图片加载失败能否正常回退。正式接入时还需验证打开、复制、编辑等既有行为及收藏和配置没有被覆盖。

交付实际截图，并简述各条目的层级、选图理由、修改文件和未解决问题。明确区分素材生成、试验预览、用户视觉认可、正式接入和部署；文件已写入不等于 Skill 已被客户端发现或执行。
