# Personal Portal 使用与维护

## 先确认目标实例

用户指定的项目目录是工作目标。先读该目录的 AGENTS.md 和 README.md，核对四份实例 JSON；不要从 Skill 安装位置推断项目路径。公共模板和个人实例通常在不同目录，不会自动同步；涉及真实链接时修改用户指定的个人实例，不把数据写回公共模板。

按任务读取参考：配置/合并读 CONFIGURATION.md；配图读 SHARE_CARD_STYLE.md；安装、卸载或迁移自启动读 AUTOSTART.md。文档缺失时明确指出，不猜测该项目具备相同能力。

## 启动或管理自启动

- 普通“打开/启动导航”：先查明目标项目和可用端口，复用已有正确服务；否则先核对目标 README 与实际文件；新实例使用 portal_server.py 启动仅绑定本机的 HTTP 服务，旧实例的启动方式迁移需单独验证并获得对应授权，不改用通用目录服务器。读取页面和配置确认是目标实例，不能只凭 HTTP 200。
- 只有用户明确要求自启动时，才调用安装脚本。在 macOS 使用项目内 install-autostart.sh，可用 --port 指定端口；先检查端口冲突，不停止其他服务。普通启动不隐含安装常驻任务。
- 卸载使用同目录 uninstall-autostart.sh。移动目录前先卸载原目录的任务；换端口先导出浏览器编辑。不要修改其他项目的 LaunchAgent、SSH 设置或系统服务。
- 不直接以公网监听解决访问问题；本 Skill 不授予发布、推送、上传配置或安装目标应用的权限。非 macOS 不调用 macOS 安装器。

## 添加、编辑和归类

服务入口进入 services.json；报告、资料、分享页面进入 shares.json。以用户指定空间为准，不自动同时加入两处。

1. 使用提供的完整 URL、名称和用途。日期未知留空；不编造地址、身份或正文事实。只有任务需要理解正文且允许访问时才读取目标页面。
2. 按 URL 标准化结果查重，保留原始 URL 的查询参数和锚点。更新既有项保留 ID、扩展字段和无关内容。
3. 优先复用分类。新增服务分类更新 instance.json 的 serviceCategories；新增分享分类更新 shares.json 的 categories 与 instance.json 的 shareCategories。排序和颜色以 CONFIGURATION.md 为准。
4. 新分享使用独立稳定 ID 和 artwork 标识，在 artwork.json 保留专属 SVG 兜底，并按下述三级策略选择配图。参考项目已有图形，不用 URL 尾段作为索引。纯文字修订保留原图。
5. 不把实例内容嵌入 index.html 或通用脚本。新增卡片不改变全局布局、密度或配色规则。

## 浏览器编辑与文件合并

文件修改不等于浏览器已更新。浏览器收藏优先，加载时不会因文件版本增加自动替换。

- 有浏览器能力时，核对目标来源的已有配置；没有能力时，请用户导出对应空间的 JSON，或将文件改动标记为待与浏览器同步。不要假定没有浏览器编辑。
- 页面编辑仅存在浏览器。导出后，按 ID/URL 对比文件与导出配置；保留用户删除和自定义字段。无法判断冲突时保留双方版本并让用户选择，不用默认配置覆盖。
- 普通条目编辑请求不等于允许替换整个浏览器空间。合并完成后，在请求授权范围内导入；否则交付合并文件并说明导入步骤。
- 不清空 localStorage、提高 version 或自动补回删除项。不要自动更改已使用实例的存储键。
- 服务和分享分别导入导出；完整备份还需 instance.json 与 artwork.json。不会自动上传或提交备份，除非用户要求。

## 检查与交付

在项目根目录运行相关检查：配置修改用 node --test config.test.cjs；自启动或服务器变化用 python3 autostart.test.py 和 python3 server.test.py。check-public.cjs 只用于保留虚构示例的公共候选稿，不是个人实例的验收条件，它也检查可达 Git 历史与下一次提交身份；未批准公开身份时失败是预期行为，不擅自修改身份或重写历史。

实际检查所改内容的搜索、分类、目标地址、保存与刷新。配图变化按 SHARE_CARD_STYLE.md 检查桌面深浅主题及手机截图。没有浏览器能力时，不宣称视觉或收藏同步通过。

交付说明：改动了哪个实例、哪些文件、是否已同步浏览器、实际执行的验证、仍未完成的事项。区分文件生成、本地运行、自启动安装、Git 提交与发布。

## 原生内容优先的三级配图

进行选图、正文提取、截图或刷新素材前，必须读取 [完整选图与内容提取流程](references/card-visual-curation.md)，不能仅凭下面的摘要批量生成封面。

1. **Level 1**：真实首页、核心架构/内容图，以及原生 HTML/CSS 的时间线、状态卡、分栏、表格和有辨识度的标题排版。没有独立 img/SVG 不等于没有视觉素材；必须实际查看并裁切最有价值的内容区块，再判断是否适合。
2. **Level 2**：确无合适原生内容时，根据可靠正文生成概念封面，延续原页面字体气质、配色与系列风格，不擅自套用玻璃、金属等异质插画，不伪造数据和界面。使用用户认可的宿主生图工具。
3. **Level 3**：保留原 artwork.json 专属 SVG；无网页、加载失败或不适合展示的服务保留白卡。暂时抓取失败不覆盖已有合格素材。

截图不是整页机械缩小。去掉大块空白、长说明和无关导航，优先让右侧时间线节点、状态数字、色条及分栏结构可辨认。逐卡保存裁切矩形与原图尺寸，保留原图，不重绘或改写源内容；局部露出不能伪装成完整数据结论。深浅色、手机与真实卡片尺寸都要实看。

无文字覆盖的右区目标约 80%–90% 原图露出；只在左侧文字与底部操作渐隐。原生内容可更轻遮罩，不能把所有截图洗成灰白。文字用局部柔边底色保护，不改变全站密度或压住操作菜单。

公版负责 card-media.js/card-media.css 的通用加载、裁切与失败回退；个人实例维护可选 card-media.json 和 assets/card-media/。映射按空间与完整 URL 关联，不因用户改名或旧 ID 失效；不提高配置版本、不更改存储键、不改写收藏。只同步框架清单中的文件，绝不把个人截图、来源 URL、真实配置或私有历史放入公版。缺映射、非法参数、缺文件或图片失败都恢复原 SVG/白卡。截图更新与框架发布分开报告。
